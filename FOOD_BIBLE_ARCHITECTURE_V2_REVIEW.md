## Decisions and implemented behavior

- Recipe UUID is Food Bible identity. Standalone owned Recipes and authorized linked Recipes appear once, even with multiple retained Dish links. New `library_index` pages by Recipe UUID; old cookbook APIs remain compatible. Existing data requires no content/identity/link backfill.
- Dish = actual cooking identity; Recipe = instructions. Food Bible creation offers Paste Recipe/Add Manually directly, without Choose Dish. Dish-context creation preserves explicit linkage. Linking/unlinking never creates/deletes cooking or changes ranking; unlink leaves the Recipe in Food Bible.
- Normal edit archives a new content revision under the same Recipe. Owner Version History supports inspection and restore-as-new-current-revision, retaining the current sharing setting. Save as New creates an independent private Recipe. Stale edits cannot recreate a deleted Recipe. Legacy archived JSON is restored exactly rather than forced through modern-edit component guards.
- Existing Recipe-based cook claims pin revision/content. Explicit `associate_cook` validates ownership/current revision and cannot replace a different pinned snapshot. A Dish link never guesses what old attempts cooked. Later Recipe edits/restores do not rewrite those snapshots. No new full social/cooking flow is implemented.
- Recipe-owned optional JPEG uses existing ImageIO preparation/SDK account-generation fences and separate private `recipe-photos` Storage. Manifest/path/hash/size are server-owned; ready bytes are required before Save and native download validates hash/JPEG. Photo → linked Dish/cook fallback → branded fallback. Replacement/removal keeps history-referenced bytes; a bounded cleanup API/policy supports unreferenced uploads. Account deletion covers all Recipe bytes before graph/Auth erasure. No cooking-photo protocol/store/schema change.
- Deterministic reader-only serving projection reuses exact rationals. Integer/fraction/decimal/count/metric/US-volume/range quantities scale without unit conversion; ambiguous/unmeasured/to-taste/as-needed/per-person amounts do not. Canonical Recipe, methods, times and snapshots remain unchanged. Explicit serving counts and existing plain-count yields are supported; vague/range/non-serving yields remain unscaled.
- First Paste Recipe use shows external-AI disclosure before text transmission, with Continue, Cancel/Add Manually and policy access. Device-local acknowledgement is versioned/account-scoped. No normal Cloud Formatting/provider/Apple-vs-cloud choice or global AI switch. Manual/cancel never invokes AI. Standard Gemini contract 3 and all accepted no-daily-cap/no-expiration/burst/cooldown/no-auto-retry/no-billing behavior remain unchanged.
- Existing optional Recipe description remains editable/removable, with guidance for 1–3 useful sentences. Recipe Contains/Possible checklist remains primary ingredient-derived information. Actual cook assertions/substitutions/dietary/legacy tags are retained in cook-specific controls; existing Avoid/filter/search semantics remain. No religious compliance or medical guarantee is inferred.
- Cuisine/Course stay independently owned: Recipe leads Food Bible with linked-Dish fallback; Dish/cook values lead Grub Rank/current cooking-post snapshots. No automatic overwrite/classification/backfill. Recipe-to-cook prefills remain reviewable; future social Recipe posts can use explicit Recipe snapshots.
